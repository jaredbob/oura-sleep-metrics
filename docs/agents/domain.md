# Domain docs

This repo uses a single-context layout.

Before exploring, read the root `GLOSSARY.md` and the ADRs in `docs/adr/` relevant to the area you are working on, when they exist. Continue if either is absent. Use the domain-modeling skill to add glossary entries or ADRs as terms and decisions are settled.

Use glossary terms in outputs such as issue titles, refactor proposals, and tests. If a term is missing, check existing project language and flag any gap for domain modeling.

If a proposal conflicts with an ADR, name the ADR and explain why the decision may need to be revisited.
